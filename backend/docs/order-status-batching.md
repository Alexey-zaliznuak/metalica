# Пакетная доставка статусов в BlueSales

Изменения сохраняются в `OrderStatusChange` сразу. От срока самой ранней доступной
задачи (`nextAttemptAt`) отсчитывается окно накопления, по умолчанию 10 секунд.
Когда оно истекает, обработчик забирает до 500 готовых изменений разных заказов,
включая поступившие в течение окна. При отсутствии изменений запросов в БС нет.
Локальное изменение статуса по-прежнему сразу видно пользователю; подтверждение
БС задерживается на окно накопления плюс очередь API и время выполнения запросов.

Настройки:
- `ORDER_STATUS_OUTBOX_BATCH_WINDOW_MS=10000` — окно накопления, мс.
- `ORDER_STATUS_OUTBOX_BATCH_SIZE=500` — размер пачки, от 1 до 500.
- `ORDER_STATUS_OUTBOX_POLL_MS=500` — частота проверки готовности очереди, мс.

Пачка группируется по целевому статусу: один `orders.updateMany` на группу и один
общий `orders.get` для проверки успешно отправленных групп. Результат проверяется
для каждого заказа отдельно. Следующее изменение того же заказа блокируется,
пока предыдущее не завершено. Промежуточные переходы не объединяются и не теряются.

После ошибки или перезапуска обработчик сначала читает текущие статусы через
общий GET. Совпавшие подтверждаются без повторной записи; несовпавшие отправляются
заново. Если проверка недоступна, запись не повторяется вслепую. Это покрывает и
случай, когда БС применил запись, но соединение оборвалось до получения ответа.
Ошибки одной группы не мешают подтверждению других. Сохранены backoff, lease и
ограничение повторов для заказа, который БС не возвращает. Миграция БД не нужна:
состояния PENDING / PROCESSING / RETRY уже хранятся в существующей таблице.

Метки в `/dev-metrics`: `order-status-batch-write` и `order-status-batch-verify`.
При 20 заказах на один статус в одной пачке штатный путь — 2 запроса вместо 40.
При редких одиночных изменениях число запросов не сокращается.

Проверки: после `npm run build` запустить
`node --test test/order-status-outbox.test.cjs` из backend. Для интеграционных
сценариев требуется `OUTBOX_TEST_DATABASE_URL`, указывающий на отдельную локальную
PostgreSQL БД `outbox_test` на `127.0.0.1`, со схемой из Prisma. Тест очищает заказы
только в этой тестовой БД; обращения к BlueSales заменены имитацией.
